## What changed
- **Library split, no behaviour change.** `src/main.rs` (2,468 lines) moved to `src/cli.rs` (`git mv`; see it with
  `git diff -C -C`: 273 lines changed), now a module of the library. The decode loop (`generate`, `GenOpts`,
  `GenStats`, `argmax`, `PREFILL_BATCH`) moved to `src/generate.rs`. `src/lib.rs` is the crate root: the module
  list (unchanged), crate-root re-exports of the 13 CLI items the modules already call as `crate::fail`,
  `crate::PREFILL_BATCH`, ... (so no other module changed), and the public API: `load` (a GGUF checked and loaded,
  errors returned instead of exiting), `Backend` / `BackendCache` / `Device` / `KvType`, `Tokenizer` / `Utf8Stream`,
  the `Lm` trait, `generate` / `GenOpts` / `GenStats`, and `serve` (the `axon serve` argv, in-process).
  Everything else stays private: the modules are private, so their `pub` items are crate-visible only.
  `src/main.rs` is `fn main() { axon::cli::main() }`.
- `src/cuda/qwen2/stream.rs`: `stream_bytes` and `ring_bounds` `pub` → `pub(crate)` (the public `Backend::Cuda`
  makes `CudaQwen2` reachable, and those two take a `pub(crate)` type: `private_interfaces` warned).
- `Cargo.toml`: explicit `[lib]` and `[[bin]]` (`test = false`, `doc = false`: the binary has no tests, and one
  name for both docs collides). Version stays 0.1.0 (it already was).
- CI: the qemu step found the test harness with `grep ... | head -1`, which with two targets could pick the
  binary's; it now takes the line for `unittests src/lib.rs`. `cargo test` also runs the lib's one doctest (the
  crate-level example, `no_run`) and builds `examples/embed.rs`; `cargo clippy --all-targets` checks lib, tests,
  bin and example.
- `examples/embed.rs`: load a GGUF, prefill, decode N tokens greedily through `axon::generate`, streaming to
  stdout exactly as `axon gen` does (same tokens and same bytes: checked in the md5 gate).
- README: "Where it stands" (the positioning sentence, the H100 board, why not vLLM) and "As a library";
  `CHANGELOG.md` (all 103 merged PRs, grouped); `docs/release-0.1.md` (draft notes, not tagged).
- Tests: none added or removed. The 14 tests that were top-level `tests::*` are now `cli::tests::*` (688 before
  and after; `scripts/test-fast-skip.txt` still matches exactly one test per entry).

## Why
Zero external users after 764 commits; the review's measurable outcome is one external issue or PR within 30
days. Embedding (Synaps on Axon without a subprocess) needs a library; a release needs a changelog and the honest
sentence. The split keeps one test harness (all tests in the lib), so `scripts/test-tier.sh`, `axon-run --shard`
and the skip list work unchanged; only the build scripts change (two rustc steps instead of one, below).

Why the CLI lives in the lib rather than in `main.rs`: `serve.rs`, `draft.rs`, `hybrid.rs`, `lm.rs`, `chat.rs` and
`sample.rs` call CLI helpers (`crate::fail`, `crate::placement`, `crate::open_model_with`, ...), and 14 tests test
CLI code; keeping the CLI in the binary would need either moving those helpers (a rewrite of shared hot files) or
a second test harness (every gate doubled). It's `#[doc(hidden)] pub mod cli` with one public item, `main`.

## Results
Binary size, builders' rustc settings (opt-level 3, codegen-units 4, no LTO, not stripped), MEASURED on bella:
main aecc49d 11,395,976 B → 380ba27 11,378,656 B (−17,320 B, −0.15 %); stripped 6,598,488 → 6,576,088 B.
`examples/embed` 9,880,920 B. `cargo build --release` (fat LTO, codegen-units 1, strip) wasn't measured: cargo
isn't usable on the build host. Build time: one rustc step of ~60 s becomes a lib step of ~60 s plus a binary link
of a few seconds; test harness unchanged (one step). No speed change expected (same code, same codegen
settings; the only new crate boundary is `main` → `cli::main`); no timing run.

## What didn't work
- First attempt kept `argmax` behind `#[cfg(test)]` at the crate root: `lm.rs` and `hybrid.rs` call
  `crate::argmax` outside tests. A grep for `crate::<item>` paths missed three more (`check_stream_decode`,
  `kv_flag`, `draft_env_set`); the compiler found them. The full list is now in `lib.rs`.

## Build-script change for builders (after this merges)
One harness for tests (as before), two steps for the binary. In a copy of `~/.cache/axon-chunk/build.sh`:
- `--test` builds: `src/main.rs` → `src/lib.rs`. Nothing else changes.
- The binary: first `rustc --crate-type rlib --crate-name axon -C metadata=axonlib -o OUT.d/libaxon.rlib src/lib.rs
  <same flags and --extern list>`, then `rustc --crate-type bin --crate-name axon -C metadata=axonbin -o OUT
  src/main.rs -L dependency=OUT.d --extern axon=OUT.d/libaxon.rlib -L dependency=<shared deps>`, with the same
  `-C opt-level=3 -C codegen-units=4` and any extra flags on both. The two `-C metadata` values must differ (both
  crates are named `axon`).
- clippy: run clippy-driver on `src/lib.rs` (`--crate-type rlib`, and `--test`) and on `src/main.rs` against
  that rlib.
- Reference scripts: `~/.cache/axon-adopt/{build.sh,clippy.sh,buildall.sh}`.
