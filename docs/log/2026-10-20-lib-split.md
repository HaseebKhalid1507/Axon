## What changed
- **Library split, no behaviour change.** The body of `src/main.rs` (2,468 lines) moved to `src/cli.rs`, now a module
  of the library. Git records this as a **new file `src/cli.rs` and a modified `src/main.rs`**, not a rename: the
  commit message's "git mv" is wrong (the mv was undone when `src/main.rs` was recreated in the same commit). Only
  `git diff -C -C` (copy detection) pairs them (273 lines changed); `git merge` and `git log --follow` don't, so
  branches that edit `src/main.rs` need the port recipe below. The decode loop (`generate`, `GenOpts`,
  `GenStats`, `argmax`, `PREFILL_BATCH`) moved to `src/generate.rs`. `src/lib.rs` is the crate root: the module
  list (unchanged), crate-root re-exports of the 13 CLI items the modules already call as `crate::fail`,
  `crate::PREFILL_BATCH`, ... (so no other module changed), and the public API: `load` (a GGUF checked and loaded,
  errors returned instead of exiting), `Backend` / `BackendCache` / `Device` / `KvType`, `Tokenizer` / `Utf8Stream`,
  the `Lm` trait, `generate` / `GenOpts` / `GenStats`, and `serve` (the `axon serve` argv, in-process).
  The modules stay private, so nothing else is nameable from outside; but `pub` items of types the API returns
  are reachable (e.g. `Backend`'s variants and their fields, `Model`'s fields): unnameable, not private. #118.
  `src/main.rs` is `fn main() { axon::cli::main() }`.
- `src/cuda/qwen2/stream.rs`: `stream_bytes` and `ring_bounds` `pub` → `pub(crate)` (the public `Backend::Cuda`
  makes `CudaQwen2` reachable, and those two take a `pub(crate)` type: `private_interfaces` warned).
- `Cargo.toml`: explicit `[lib]` and `[[bin]]` (`test = false`, `doc = false`: the binary has no tests, and one
  name for both docs collides). Version stays 0.1.0 (it already was).
- CI: the qemu step found the test harness with `grep ... | head -1`, which with two targets could pick the
  binary's; it now takes the line for `unittests src/lib.rs`. `cargo test` also runs the lib's one doctest (the
  crate-level example, `no_run`) and builds `examples/embed.rs`; `cargo clippy --all-targets` checks lib, tests,
  bin and example.
- `examples/embed.rs`: load a GGUF, prefill, decode N tokens greedily through `axon::generate`, streaming to
  stdout exactly as `axon gen` does (same tokens and same bytes: checked in the md5 gate).
- README: "Where it stands" (the positioning sentence, the H100 board, why not vLLM) and "As a library";
  `CHANGELOG.md` (all 103 merged PRs, grouped); `docs/release-0.1.md` (draft notes, not tagged).
- Tests: none removed. The 14 tests that were top-level `tests::*` are now `cli::tests::*` (round 1); in round 2,
  the 5 that test `generate.rs` code (`argmax_*`, `best_matches_argmax`, `generate_uses_the_lm_seam`) moved to
  `generate::tests::*`, and `tests::kv_f32_after_f16_is_an_error` is new (689 tests; `scripts/test-fast-skip.txt`
  still matches exactly one test per entry).

## Why
Zero external users after 764 commits; the review's measurable outcome is one external issue or PR within 30
days. Embedding (Synaps on Axon without a subprocess) needs a library; a release needs a changelog and the honest
sentence. The split keeps one test harness (all tests in the lib), so `scripts/test-tier.sh`, `axon-run --shard`
and the skip list work unchanged; only the build scripts change (two rustc steps instead of one, below).

Why the CLI lives in the lib rather than in `main.rs`: `serve.rs`, `draft.rs`, `hybrid.rs`, `lm.rs`, `chat.rs` and
`sample.rs` call CLI helpers (`crate::fail`, `crate::placement`, `crate::open_model_with`, ...), and 14 tests test
CLI code; keeping the CLI in the binary would need either moving those helpers (a rewrite of shared hot files) or
a second test harness (every gate doubled). It's `#[doc(hidden)] pub mod cli` with one public item, `main`.

pending). Round 2's `axon` is 11,378,584 B; the devstack helper builds a byte-identical binary.

## Round 2 (Shady's review: MUST 1–5, two SHOULDs)
- **Claims scoped** (README "Where it stands", the Numbers paragraph, docs/release-0.1.md): the lowest ITL p99 is
  one cell (*mix*, C = 128; and C = 1); Axon's ITL p99 is the highest of five on *classic* from C = 8 up and on *mix*
  at C = 8 (table added, re-derived from `cells.jsonl`); "3× behind" → 2.0–3.8× (*mix*) / 1.8–3.2× (*classic*);
  cold start "with the shipped kernel cache".
- **`GenOpts::greedy`** (MUST 4): `GenOpts.sample` is `pub(crate)`; embedders build greedy options with
  `GenOpts::greedy(n, stop)` (and may set `max_draft`). Why not export `Sampler`: its settings are validated only by
  the CLI's `SampleArgs::resolve`, so a public constructor means a new validated API plus tests; greedy-only is the
  smaller safe option for 0.1 and is what reproducible-bits users want first. Sampling for embedders: #118.
- **KV type** (MUST 5): `Backend::new`/`new_capped` check `AXON_KV` (an `Err`, not the later panic in
  `kv::use_f32`), then fix the process's CPU cache type from `kv` (`F32` → f32, else f16) and refuse a conflict with
  an earlier choice. The CLI always passes the type `AXON_KV`/`--kv` imply, so its behaviour is unchanged (checked
  case by case: `--kv f16|q8` set f16 first; `AXON_KV=f32` without `--kv` passes `F32`).
- Tests for `generate.rs` moved into it; a speed A/B (tg128, pp512, 1.5B) is in the gates.
- Builders: the devstack scripts that build Axon handle both layouts (devstack branch `lib-split-builds`).

## Porting a branch that edits `src/main.rs`
`git merge origin/main` gives a modify/modify conflict on `src/main.rs` (now 3 lines) and leaves `src/cli.rs`
without the branch's edits. Port the patch instead:
```bash
BASE=$(git merge-base origin/main HEAD)          # the pre-split base of your branch
git merge origin/main                             # conflict in src/main.rs
git checkout --theirs src/main.rs && git add src/main.rs     # take main's 3-line main.rs
git diff "$BASE" HEAD -- src/main.rs | sed 's#src/main.rs#src/cli.rs#g' > /tmp/main-to-cli.patch
git apply -3 /tmp/main-to-cli.patch               # 3-way, from main.rs's blobs onto cli.rs
```
- Hunks in CLI code apply (tested on a scratch branch: an edit in `run_lm` applied cleanly).
- Hunks in code that moved to `src/generate.rs` (`generate`, `GenOpts`, `GenStats`, `argmax`, `PREFILL_BATCH`, and
  their tests) come back as one conflict in `src/cli.rs` whose "ours" side is empty and whose "theirs" side is the
  whole old block: delete that region and redo those hunks by hand in `src/generate.rs` (they're in the patch file).
- Check: no conflict markers (`grep -n '^<<<<<<<\|^>>>>>>>' src/cli.rs src/generate.rs`), every hunk of the patch is
  in `git diff origin/main -- src/cli.rs src/generate.rs`, then build and test as usual.

## Build-script change for builders (after this merges)
One harness for tests (as before), two steps for the binary. In a copy of `~/.cache/axon-chunk/build.sh`:
- `--test` builds: `src/main.rs` → `src/lib.rs`. Nothing else changes.
- The binary: first `rustc --crate-type rlib --crate-name axon -C metadata=axonlib -o OUT.d/libaxon.rlib src/lib.rs
  <same flags and --extern list>`, then `rustc --crate-type bin --crate-name axon -C metadata=axonbin -o OUT
  src/main.rs -L dependency=OUT.d --extern axon=OUT.d/libaxon.rlib -L dependency=<shared deps>`, with the same
  `-C opt-level=3 -C codegen-units=4` and any extra flags on both. The two `-C metadata` values must differ (both
  crates are named `axon`).
- clippy: run clippy-driver on `src/lib.rs` (`--crate-type rlib`, and `--test`) and on `src/main.rs` against
  that rlib.
- Reference scripts: `~/.cache/axon-adopt/{build.sh,clippy.sh,buildall.sh}`.
- The automated builders (axon-devstack `bin/axon-postmerge`, `bin/axon-train`, `runbooks/h100sd/build-axon.sh`)
  build both new heads and pre-split bases, so they pick the recipe per tree: two steps if `src/lib.rs` exists, else
  the old single step (devstack branch `lib-split-builds`, merged with this PR).
- No builder gate compiles `examples/embed.rs` or runs the doctest; GitHub CI does (`cargo test`,
  `cargo clippy --all-targets`), and this PR's md5 gate runs the example.
