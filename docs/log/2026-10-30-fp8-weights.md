# FP8 weights: per-channel e4m3 checkpoints, exact mode as Q8_0, a native fast path that misses its bars (PR #177)

- Date: 2026-10-29 – 10-30. Branch: feat/fp8-weights. Base: main 452a7d4 (#173). Track WP-A2 of the beat-vLLM scope
  (`specs/beat-vllm-scope.md` §6). Design and full results: [fp8-weights.md](../design/fp8-weights.md) (§10–§12).
- Decision: Haseeb, 2026-10-29 ("go"). Ruling on the results: lead, 2026-10-30 (below).

Labels: **MEASURED** (job cited), **CODE**, **OPINION**.

## What changed (CODE)

- Loader: compressed-tensors FP8-dynamic (per-channel e4m3 weights + a weight_scale per row, dynamic per-token
  activations) is accepted; every other FP8 form is refused by name.
- Exact mode (the default): the FP8 matrices become Q8_0 at load and run on today's kernels. GGUF bits are unchanged
  (md5 gate).
- `--numerics fast`, sm_89+: `quant_f8_tok`, `gemv_f8` (nb ≤ 16), `gemm_f8` (mma.sync e4m3, nb > 16), with the
  Hopper wgmma seam (`f8_route`) left for WP-A3. `NUMERICS_VERSION_FAST` 1 → 2, so GGUF fast fingerprints move to
  `fast/1.2`.
- The CPU runs the exact dequant (fp8-ref): it is the accuracy reference.

## Results (MEASURED)

**Accuracy, 7B** (vs fp8-ref, 32 windows, 5823 positions; 1029-201935-949b / -bd1a):

| | KL mean | top-1 |
|---|---|---|
| fast, decode | 4.56e-3 | 95.86 % |
| fast, batched | 4.49e-3 | 95.99 % |
| exact (Q8_0) | 1.21e-3 | 98.06 % |
| Q4_K_M | 2.39e-2 | 92.00 % |

The bars are KL ≤ 0.01 and top-1 ≥ 97 %. Fast passes KL and fails top-1. On the same windows the GPU matches its
own CPU emulation (95.3 % vs 96.1 %), so the miss comes from the W8A8 format. The 0.5B gave the same result against
HF F32 (fast 94.4 %, exact 96.7 %).

## Ruling (lead, 2026-10-30)

- Fast FP8 on bella fails both pre-registered bars: decode is 32 against 47–55, and 7B top-1 is 95.9 % against 97 %.
- #177 ships as the loader plus exact mode, which is the default and passes both accuracy bars.
- Fast FP8 stays behind `--numerics fast`. It is documented as failing its bars on sm_120 and is unmeasured on an
  H100.

## Follow-up

- **FP8 fast decode.** An FP8-native net runs a single token as a one-row batched pass, with no decode-step kernels
  and no CUDA graphs (CODE), and that is where the decode time goes (OPINION). The fix is to give F8 nets the
  decode-graph GEMV path, then re-gate on bella and on an H100.
- Not run: an HF BF16 reference for the 7B, sm_89 runs of the graded gate and the kernel checks, and the H100 tg128
  bar. All three need pods.
