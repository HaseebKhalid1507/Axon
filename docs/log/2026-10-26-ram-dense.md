# Dense CPU loads refused when they can't fit in the RAM available  (PR #PRNUM)

- Date: 2026-10-26. Branch: fix/ramdense. Base: main 39624db, merged up to 161e787 (docs only). Status: open
- Pick / design: issue #135 (follow-up of #133 / #129).

## What changed
- `model::check_ram_dense(m, ctx)` runs for every dense model built for the CPU (`Backend::new_capped`, next to the
  MoE `moe_check_ram`). It compares the r8 arena (`dense_ram_need`: the output head and every layer matrix with an
  r8/r8q form, laid out exactly as `Qwen2::build` does, in 2 MB pages) plus the KV cache for the context against
  `gguf::mem::avail()`. That figure is the host's `MemAvailable`, or the room under the tightest cgroup limit
  (#133). The refusal names the bound:
  `qwen2: the CPU model needs about 0.39 GB of RAM (its repacked weights 0.39 GB, a 14-token KV cache 0.00 GB) and
  only 0.28 GB is available (bound by cgroup /…/x.scope memory.max 320 MB); a smaller --ctx, a smaller model or more
  memory`.
- KV context: the explicit one (`gen`: prompt + `-n`; `--ctx`). When the context is left to fit (serve's
  `cpu_ctx`, which shrinks it to the RAM), the floor it can shrink to: min(ctx, DEFAULT_CHAT_CTX).
- The file isn't counted (#128's lesson): mapped, its pages are reclaimable page cache; copied (a model that reads in
  place), it's already in use when the check runs, so the available figure excludes it.
- No headroom on top. See "What didn't work".

## Why
#135 / job 1025-054259-1d9c: qwen2.5-0.5b `gen --device cpu` under `MemoryMax=400M` was OOM-killed (rc 137) on main.
Only MoE models had a RAM refusal. Containers and systemd scopes run under memory limits, and an OOM kill gives the
operator nothing to act on.

## What didn't work
- **32 MiB of headroom** (scratch, side copies) on top of arena + KV: job 1025-224358-e406 refused all six models at
  exactly the smallest cap main runs at, each 10–20 MB short. The arena and KV are anonymous memory the run touches,
  so a load that fits has at least that much available at the check. With no headroom the check can't refuse a load
  that fits. The price: a limit between the arena and arena + scratch (tens of MB; the band between "refused" and
  "smallest working cap" above) is still an OOM kill, not a refusal.
