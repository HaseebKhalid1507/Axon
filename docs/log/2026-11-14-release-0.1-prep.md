## Stop rule and protocol (written 2026-11-14 ~20:00 EST, before any board ran)

All on bella (RTX 5070 Ti Laptop, sm_120, 12 GB), `axon-run --timing bella` (exclusive, after the #228 soak).
**Axon is the release dry run's own binary** (the workflow's tarball for `9f3630c`, kernel pack embedded), not a
local build. Scripts: `scripts/release/boards/` in this PR (bella's paths; each job's `hw.txt` records the
harness commit and every input's SHA-256).

**Agent replay.** Cell agent-32k as in [the 10-27 board](2026-10-27-agent-replay.md): `board-trace-v1.json`, the
10-minute window with the most sessions, scale 0.15, clip 32,768; Qwen2.5-7B-Instruct Q4_K_M (sha256
`65b8fcd92af6…`); f16 KV. llama-server gets Axon's paged-pool size as its KV budget (`--kv-tokens`), as before.
1. **llama-server tuned by its own side** (sweep, one speed-1 round per arm):
   - axon: the reference run, whose pool is the budget;
   - A0: bella's llama.cpp `4413a19` (2026-10-13), the board's defaults (`-np budget//32768 -c np·32768 -kvu
     --cache-reuse 256 -fa on`): the 10-27 and weekly boards' configuration;
   - A1: upstream's official Linux CUDA 13.5 build of master b12387 (`a956a852c`, 2026-11-14), the same defaults;
   - A2: A1 + `--no-cache-idle-slots`. By default llama-server saves *and clears* every idle slot on each new
     task under unified KV (`server-context.cpp`, b12387), so each resumed turn reloads its context from RAM;
   - A3: A2 + `-ub 2048` (a turn's ~1.1k new tokens in one micro-batch);
   - A4: A1 with twice the slots on the same pool (`-np 2·np -c budget`; idle slots cleared, so more concurrency);
   - A5: A2 + `-cram 16384` (twice the RAM prompt cache: 20 sessions' contexts don't fit in 8 GiB).

   **Winner:** among arms with 0 errors, 0 prompt-count mismatches, not tainted and every turn measured (n turn =
   axon's), the lowest TTFT-turn p50; arms within 5 % of it tie, and the lowest ITL p99 among them wins, then the
   lowest TTFT-new p50. A tainted arm runs once more at the end and its rerun counts if clean. No arm qualifies:
   no board, and this log says so.
2. **The board:** axon vs the winner, speeds 1 and 4, 3 interleaved rounds, a fresh engine process per cell
   (`agent_replay.py board`). No ollama: no claim here is about it.
3. **Reading (the roadmap's stop rule):** speed 1's TTFT-turn p50, the median over clean rounds (at least 2;
   fewer: no verdict, rerun). R = llama-server / axon.
   - **R ≤ 1.5:** the edge is thinner than claimed. The notes say so with the numbers, and MoE in the paged pool
     goes first in the roadmap (item 7).
   - **R > 1.5:** the notes state R as measured (bella, `9f3630c`, llama-server's winning configuration), with
     ITL p99 beside it.
   - The tag goes ahead either way. Speed 4 is reported, not read (it overloads every engine).

**Single stream.** The weekly pod board's script, unchanged (axon-devstack `pod/board/sb_pod.py`, hashed): per
model the GPU cooled, 3 interleaved rounds, salted prompts; axon `gen --device cuda` pp560 / pp2100 / tg128
against `llama-bench -fa 1 -b 4096 -ub 512,4096 -r 3`, both b12387 (above) and `4413a19`; Qwen2.5 0.5B / 1.5B / 3B
/ 7B Instruct and Qwen3 8B, Q4_K_M. **Reading:** per cell, axon's median over llama.cpp b12387's (its best
ubatch); within ±2 % is parity, else ahead or behind. The notes give the counts and the thinnest margins; nothing
from this board is called a lead where the cell is parity.

**No pod.** A 4090 board isn't needed for any line in the notes: the 4090 numbers there are dated to `7f42c02`.
The weekly 4090 board (axon-weekly, Sundays 06:00, Process v2 rule 3) runs on main's tip anyway.
