maintainer's (docs/release-0.1.md). This PR does everything before that: the release notes and the CHANGELOG for a

## Stop rule and protocol (pre-registered at `717c487`, 2026-11-14 19:34 EST; amended before any board ran)

The rule was first committed at `717c487` (19:34 EST), before the jobs were queued (19:40). Shady's review of #270
found holes in it that only went one way, and it was amended (below) while every board job was still queued
behind bella's hold: no measurement existed. The amendment's commit and time are in the PR body. The old jobs were
killed and resubmitted on the amended scripts; what changed is listed at the end of this section.

All on bella (RTX 5070 Ti Laptop, sm_120, 12 GB), `axon-run --timing bella` (exclusive, after the #228 soak).
**Axon is the release dry run's own binary** (the workflow's tarball for `9f3630c`, kernel pack embedded), not a
local build, with `AXON_KERNEL_PACK=only`: NVRTC refused, so a broken pack fails the board. Scripts:
`scripts/release/boards/` in this PR (bella's paths). Each job's `hw.txt` records the harness commit and scripts
tree, the `AXON_*` environment, `axon kernels list`, every input's SHA-256 and each llama.cpp build's CUDA archs
(`cuobjdump`). A real run refuses uncommitted scripts and any `AXON_REL_*` override of the protocol, and starts
only after a smoke of the same scripts tree passed (`need_smoke`).

**Agent replay.** Cell agent-32k as in [the 10-27 board](2026-10-27-agent-replay.md): `board-trace-v1.json`, the
10-minute window with the most sessions, scale 0.15, clip 32,768; Qwen2.5-7B-Instruct Q4_K_M (sha256
`65b8fcd92af6…`); f16 KV. llama-server gets Axon's paged-pool size as its KV budget (`--kv-tokens`), as before.
llama-server b12387 gets its library path through `--llama-env`; axon never runs under it.
1. **llama-server's configurations** (sweep, one speed-1 round per arm): seven chosen to favor it, from llama.cpp's
   source, A6 from the reviewer arguing its side:
   - axon: the reference run, whose pool is the budget (it sets the budget and is not judged);
   - A0: bella's llama.cpp `4413a19` (2026-10-13), the board's defaults (`-np budget//32768 -c np·32768 -kvu
     --cache-reuse 256 -fa on`): the 10-27 and weekly boards' configuration;
   - A1: upstream's official Linux CUDA 13.5 build of master b12387 (`a956a852c`, 2026-11-14), the same defaults;
   - A2: A1 + `--no-cache-idle-slots`. By default llama-server saves *and clears* every idle slot on each new
     task under unified KV (`server-context.cpp`, b12387), so each resumed turn reloads its context from RAM;
   - A3: A2 + `-ub 2048` (a turn's ~1.1k new tokens in one micro-batch);
   - A4: A1 with twice the slots on the same pool (`-np 2·np -c budget`; idle slots cleared, so more concurrency);
   - A5: A2 + `-cram 16384` (twice the RAM prompt cache; with idle slots kept it is barely used, so A5 ≈ A2);
   - A6: A1 + `-cram 16384`: idle slots still saved and cleared, with a RAM cache that holds all 20 sessions (the
     save-and-restore path llama.cpp built for unified KV).

   **Clean** (one definition for every engine, `pick.py`'s `why_not`): 0 errors of any kind (aborted streams
   included), 0 prompt-count mismatches, not tainted, and every request and turn of the plan sent and measured
   (requests = the plan's, n turn = the plan's: `agent_replay.py`'s `plan_counts`, never another engine's count).
   **Winner:** the clean arm with the lowest TTFT-turn p50, full stop (an exact tie, to the millisecond: the lower
   TTFT-new p50). ITL p99 is reported for every arm, not used. A tainted arm runs once more at the end and its
   rerun counts if clean. No clean arm: no board, and this log says so. `pick.py --selftest` checks this on fake
   sweeps.
2. **The board:** axon vs the winner, speeds 1 and 4, 3 interleaved rounds, a fresh engine process per cell
   (`agent_replay.py board`), the engine order reversed on odd rounds (`--rotate-engines`), llama-server on the
   sweep's budget (`--kv-tokens` = `sweep/POOL`, the budget its winner won on), the GPU's temperature and clocks
   recorded before and after every run. No ollama: no claim here is about it.
3. **Reading (the roadmap's stop rule; `read_board.py`, `--selftest` on fake boards):** speed 1's TTFT-turn p50.
   - A round counts only if **both** engines' runs in it are clean (above). Fewer than 2 such rounds: no verdict;
     the rounds are rerun and nothing is read.
   - **R** = the median over the counted rounds of llama-server's TTFT-turn p50, divided by the median over the
     same rounds of axon's (a ratio of medians; R > 1: axon is faster). **The round spread**: the per-round ratios
     llama-server / axon over the counted rounds, min to max. Both engines' errors, mismatches and turn counts are
     printed per round.
   - The verdict, the first that applies:
     - **Every counted round's ratio < 1:** "llama-server leads on turn TTFT, by 1/R". That goes in the notes'
       one-sentence summary, not only in a bullet.
     - **The round spread includes 1:** "level with llama-server on turn TTFT (R, the spread)". Also in the
       one-sentence summary.
     - **R ≤ 1.5:** axon leads by R, thinner than the 10-27 8.7×. The notes say so with the numbers.
     - **R > 1.5:** the notes state R as measured (bella, `9f3630c`, llama-server's winning configuration), with
       ITL p99 beside it.
     - R ≤ 1.5 in any branch: MoE in the paged pool goes first in the roadmap (item 7). The 10-27 line is marked
       superseded by the new R either way.
   - The tag goes ahead either way. Speed 4 is reported, not read (it overloads every engine).

**Single stream.** The weekly pod board's protocol: `scripts/release/boards/sb_pod.py` is axon-devstack's
`pod/board/sb_pod.py` (`954985e6…`) changed in four marked places: the run order rotates by round (round r starts
with unit r of axon, b12387, 4413a19: a Latin square), the GPU's state is recorded before every run, every sample
goes to `sb.json`, and `cool()` parses a fractional temperature (driver 620.70.06 reports `86.59`; the original's
`int()` raised before the first run, on bella and avante alike). Per model the GPU cooled, 3 rounds, salted prompts;
axon `gen --device cuda` pp560 / pp2100 / tg128 against `llama-bench -fa 1 -b 4096 -ub 512,4096 -r 3`, both b12387
(through a wrapper the script writes and hashes) and `4413a19`; Qwen2.5 0.5B / 1.5B / 3B / 7B Instruct and Qwen3 8B,
Q4_K_M. **Reading (`sb_read.py`, `--selftest` on fake data):** per cell, axon's median against the **faster** of the
two llama.cpp builds' medians, each at its best ubatch per round. AHEAD: the margin is over +2 % **and** every axon
round beats every round of that build; BEHIND: under −2 % and every axon round is below every round of that build;
else parity. The notes give the counts, the thinnest AHEAD margins, the worst margins (the biggest losses,
whatever their verdict) and every BEHIND cell. Nothing parity is called a lead. The -ub 512 runs are printed too,
as the 10-18 board's protocol (`llama-bench -ngl 99 -r 1`, other options at their defaults: `-ub 512`).

**Smokes.** The two smokes (the agent sweep and board, and single stream, on the 0.5B with the release binary,
next to other GPU jobs) gate the real runs: the real jobs are submitted only after both pass, and each real script
checks for its smoke's marker on the same scripts tree.

**No pod.** A 4090 board isn't needed for any line in the notes: the 4090 numbers there are dated to `7f42c02`.
The weekly 4090 board (axon-weekly, Sundays 06:00, Process v2 rule 3) runs on main's tip anyway.

**What the amendment changed from `717c487`** (shady's #270 review: MUSTs 3–5; SHOULDs 1, 4–8):
- The winner was the lowest ITL p99 among arms within 5 % of the best TTFT-turn p50; it is now the lowest TTFT-turn
  p50, the verdict's own metric. The old tie band leaned toward an arm slower on that metric.
- An arm qualified on n turn = **axon's**, so axon's own failed turns would have disqualified every full arm. It is
  now the plan's count, and the request count too.
- The board's "clean round" was "not tainted" only, and axon's errors were checked nowhere; a round now counts
  only if both engines are clean by the same definition.
- R is defined (a ratio of medians over paired clean rounds), and wording is fixed in advance for R < 1 and for a
  round spread that includes 1.
- Single stream was read against b12387 only; it is now read against the faster of the two builds, AHEAD/BEHIND
  need the round ranges apart as well as 2 %, and the worst losses are reported.
- Added: arm A6; the engine order rotated (agent board) and the run order rotated (single stream); the board on the
  sweep's KV budget; `AXON_KERNEL_PACK=only`, the library path scoped to llama-server; the llama-bench that runs
  hashed, each build's CUDA archs and the `AXON_*` environment in `hw.txt`; the smokes as a gate.
