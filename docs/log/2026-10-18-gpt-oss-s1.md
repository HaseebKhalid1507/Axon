# gpt-oss stage 1: attention, sinks, windows and router on the GPU, MXFP4 experts on the CPU

2026-10-18. Branch `feat/gpt-oss-gpu` (on main 953b886). Status: in progress. The real-model correctness gates
are pending; see "Gates" below.

## Why

Stage 0 (#78) runs gpt-oss-20b on the CPU only, exactly. The model is 12.1 GB: experts 10.15 GB plus 1.94 GB for
everything else, so bella's 12 GB card can't hold it all. Stage 1 is #67's split, as for qwen3moe: attention (with
the sinks and the alternating 128-token window), norms, router and output head on the GPU, and the MXFP4 experts
on the CPU, read in place from the mapping (no repack, no copy).

## What changed

- **`src/cuda/oss.cu`** (new). It's appended to the dense kernel source as a module of its own
  (`Kernels::module_for` on a gpt-oss model; `kernels_src!` in cuda/mod.rs), so the dense models' source, cache key
  and cubin are unchanged.
  - `attn_split_ws_64`: decode.cu's split attention `attn_split_t<64>` over the query's window
    `[win_lo(np, win), np)`, through the page table if there is one.
  - `attn_combine_ws`: decode.cu's combine with the sink. The sink is a score with no value row: it goes into the
    max over the splits' maxima, and adds `exp(sink - M)` to the normalizer (`soft_max_ext` with sinks, as the CPU's
    `vmath::softmax_sink`).
  - `attn_split_bws_64` / `attn_combine_bws`: the batched twins. They run the same device code per query token,
    so decode == batched prefill, bit for bit.
  - Head size 64 only, f16 KV only, no tensor-core attention (the split path, as gemma3's).
- **`src/cuda/moe.cu`**: `moe_topk_oai` (added; the other kernels untouched). It adds the router bias to the logits,
  takes the top k by tree argmax (ties go to the lower index), and makes the weights the softmax over those k in rank
  order (as `Moe::route_oai`). `moe_logits` (the FFN norm and the logits) is shared with qwen3moe.
- **`src/cuda/qwen2.rs`, `batch.rs`, `qwen2/moe.rs`**: a gpt-oss arm, additive.
  - `LayerW::oss` holds the window, sinks, output bias and router bias. The pre-FFN norm is `post_attention_norm`.
  - The local layers keep the global (YaRN) RoPE table.
  - `enqueue_attn` / `attn_half` launch oss.cu's kernels and add `x += W_o act + b_o` (the gemv/bgemm bias).
  - `moe_route` uses `moe_topk_oai`.
  - The q8 KV cache and head sizes other than 64 are refused.
- **`src/model/moe.rs`**: `cpu_only` is deepseek2 only now, so `--device cuda` on gpt-oss builds `MoeQwen3`
  (`Backend::Moe`).
- Tests: `src/moe/oss_tests.rs`, plus `oss_fixture_dims` (the stage-0 fixture at other dimensions) and
  `teacher_forced_dump` `AXON_TF_DEV=moe`.

## Speed (MEASURED, bella: RTX 5070 Ti Laptop sm_120 12 GB, driver 615.71.09, Core Ultra 9 275HX; exclusive `--timing bella`, job 1018-092300-3a16, binary 8513a25)

Method: one warm-up, then 3 interleaved rounds. Each round runs axon cuda (AXON_THREADS 8, 16, 24), llama.cpp, and
axon cpu (24). Medians are over the rounds; temperatures are logged before each run (GPU 55-68 C, CPU package up to
100 C in rounds 2-3).
- axon: `axon gen <model> <prompt> -n 128 --device cuda|cpu`. The prompt is the first 274 words of stage 0's
  pp-prompt.txt, **486 tokens** (raw text, no template); gen sized the context to 615.
- llama.cpp 4413a19 `build-cuda/bin/llama-bench -ngl 99 -ot exps=CPU -t 8,16,24 -fa on,off -p 512 -n 128 -r 1`,
  per round. llama-bench's prompt is **512** synthetic tokens. The prefill columns are not the same prompt length:
  486 vs 512 tokens. Prefill tok/s at 486 vs 512 tokens should be close, but this isn't a same-length comparison.
- ollama: no gpt-oss model is loaded (`ollama list`), and importing it would copy 12 GB onto a disk at 90%. Not run.

- **Decode**: axon cuda 46.6 vs llama.cpp's best 23.4, **1.99x**. The split is 1.64x axon's own CPU-only model.
- **Prefill**: axon cuda 265 vs llama.cpp's best 995, **0.27x** (486 vs 512 tokens). Axon's prefill scales with
  the CPU threads and is near its CPU-only rate, because its experts run on the CPU (batched per expert, compute-bound).
  llama.cpp offloads the expert GEMMs of any batch >= 32 to the GPU (`ggml_backend_cuda_device_offload_op`,
  `GGML_OP_OFFLOAD_MIN_BATCH` default 32), copying the experts over PCIe per ubatch. Diagnosis and plan (stream the
  experts through the GPU with a bit-exact MXFP4 kernel, ESTIMATED ~3-4x at pp512):
  `specs/gptoss-prefill.md` (workspace).
- Round 1's axon prefill numbers are low (120-187), consistent with the CPU warming. Rounds 2 and 3 agree within 2%.
