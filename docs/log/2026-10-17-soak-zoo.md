# Soak harness and model-zoo sweep  (PR #PRNUM)

- Date: 2026-10-17. Branch: feat/soak-zoo. Base: main 54a75cb (rebased onto REBASE before the PR). Status: open.
- Pick / design: roadmap item 2 (real-world hardening), the parts left after #37 (fuzzers) and #61/#62 (serve
  ops): a multi-hour soak under realistic load, and a sweep of GGUFs from the wild.

## What changed
- `scripts/soak.py` (new, stdlib): starts `axon serve`, runs N clients on a weighted mix for hours (chat
  streamed/whole, greedy/sampled, tools with a tool-result turn, `/v1/completions`, long prompts, a shared-prefix
  agent, mid-stream disconnects, slow readers, oversize and invalid requests, bursts of 3x the slot count), samples
  RSS/VmHWM, per-pid VRAM, fds, threads, latency and TTFT p50/p99 and counts by class every 30 s into CSV, runs
  greedy identity spot checks before, every 15 min under load and after, and gives a PASS/FAIL verdict
  (method and thresholds: [../hardening.md](../hardening.md)). `soak.py summarise` turns a CSV or a job log into
  the bucketed tables below.
- `scripts/zoo.py` (new, stdlib): fetches a list of GGUFs (sha256 recorded), runs `axon info`, greedy `gen -n 64`
  and top-20 logprobs against llama.cpp's CPU server on the same token ids, or checks the refusal is clean.
- `src/gguf.rs`: GGML types Axon can't size (IQ1_S..IQ4_XS, I8..F64, Q4_0_4_4/4_8/8_8, TQ1_0/TQ2_0,
  IQ4_NL_x_y, MXFP4) now have names (`UNSIZED_NAMES`). They stay unsized: only their offset is checked on
  load, as before (`sized()` replaces the `name == "??"` test).
- `src/model.rs` `check_supported`: the unsupported-type refusal (`unsupported_type`) names the type, lists what is
  supported, lists every unsupported type in a mixed file, and says which file to get instead.
- `docs/hardening.md` (new): fuzz/soak/zoo method, soak results, the zoo table.

## Why
Nobody had run Axon under hours of mixed real traffic, or fed it GGUFs it wasn't developed against.

The zoo's first run on main (job 1017-171548-0e4e) found one class of bug: **unclear refusals**. Every i-quant
or repacked file was refused with `type ?? (20) is not supported (F32, F16, ...)`. That covers
mradermacher's i1-IQ2_M, unsloth's IQ4_NL and its "UD-Q4_K_XL" (IQ4_XS in some layers), and the ARM Q4_0_4_4. A
user can't tell from `??` what's wrong, and for an "IQ2_M" file the first unsupported tensor is IQ4_NL, which
looks unrelated to the file's name. After the fix:

```
tensor blk.0.attn_q.weight: type IQ4_NL (20) is not supported (supported: F32, F16, Q4_0, Q4_1, Q5_0, Q5_1, Q8_0,
Q4_K, Q5_K, Q6_K) (the file has unsupported tensors: 24 IQ4_NL, 144 IQ2_S, ...); i-quants (IQ*) and ternary (TQ*)
types are not supported: use a K-quant file (Q4_K_M, Q5_K_M, Q6_K) or Q8_0
```

Also found, not a bug: bartowski's Qwen2.5-0.5B Q2_K and Q3_K_M files hold IQ4_NL tensors. 896 columns aren't
whole 256-blocks, so llama.cpp falls back to IQ4_NL for those rows. Q2_K/Q3_K kernels alone won't make them run
(posted on the forum for the Q2_K/Q3_K track).

## What didn't work / caveats
- The first bella smoke (1017-170752-c9c1) "failed" VRAM: it judged the whole card's memory while another job
  shared the GPU. The VRAM check now uses only the server pid's `nvidia-smi --query-compute-apps` row; the card
  total is recorded but not judged unless `--vram-card` is given.
- axon-run runs scripts on bella only. The avante and jade soaks ship as a package (axon binary, soak.py,
  run.sh) behind a small ELF trampoline. axon-node appends `--test-threads N` on low-memory hosts, so the
  trampoline drops that flag.
- The first jade run used `--max-queue 2` and clients that retried at once, so it was mostly 503s. Clients now
  back off 1–3 s after a 503, and jade runs with `--max-queue 4`.
