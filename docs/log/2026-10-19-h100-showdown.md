- Date: 2026-10-19 (pod 20:51–21:38 EDT). Run id: `h100-1019-2058`. Branch: docs/refresh-20261019. Base: main 764792f.
  Binary under test: main **c15c90e** (the 10-19 merge train, [log](2026-10-19-merge-train.md)). Status: published
  by this docs PR.
- Pick / design: the datacenter row of the roadmap's [mission table](../roadmap.md#mission-and-positioning) said
  "no H100 board at C ≥ 8 exists". Haseeb approved $7 for this run once #71 / #84 / #100 / #98 had landed.
  Runbook: axon-devstack `runbooks/h100-serving-showdown.md` (§1–5 what runs, hardware, engines, binary, workload;
  §7 run order; §8 cost model; §10 honest limits). Kit: `runbooks/h100sd/` (`sd_driver.py`, `sd_client.py`,
  `sd_table.py`, `pod_setup.sh`, `sd-pod.sh`).

## Short version (MEASURED, one pod, 2 rounds)

- **C = 1: Axon is fastest, narrowly.** mix 287 tok/s vs 235–284; classic 304 vs 240–296. Over vLLM that is +20–27 %;
  over SGLang-AWQ only +1 % (mix) and +3 % (classic), inside what one pod can settle (runbook §10: margins under ~5 %
  need a second pod). Best TTFT p50 at C = 1 (mix 14.6 ms vs 18.1–27.5).
- **C ≥ 8: Axon loses on throughput, and the gap widens with C.** At C = 128: mix **1,868** vs vLLM-AWQ 5,748,
  SGLang-AWQ 3,770, vLLM-FP8 7,146, SGLang-FP8 7,135 (2.0–3.8× behind); classic **4,485** vs 12,190 / 8,288 / 14,205 /
  14,380 (1.8–3.2× behind). Already at C = 8: mix 795 vs 1,096–1,212.
- **Latency under load is mixed, not a win.** Axon's ITL p99 is the lowest of the five only at mix C = 128
  (77.5 ms vs 126–320): its steps are uniformly slow rather than spiky (ITL p50 58.0 ms there, vs 5.2–10.8). On
  classic its ITL p99 is the highest from C = 32 up (51.7–62.0 ms vs 5.2–39.7). TPOT p50 grows from 3.2 ms (C = 1) to
  57.9 ms (mix C = 128); the others stay at 12.7–26.4 ms.
- **Goodput collapses at high C.** Under the SLO (TPOT ≤ 50 ms, TTFT ≤ 2 s + 0.25 s per 1k prompt tokens) Axon keeps
  25.6 % of mix requests at C = 128 (goodput 513 tok/s vs 2,645–7,129) with TTFT p99 14.5 s (others 1.9–5.3 s).
- **Quant formats differ** (Q4_K_M GGUF vs AWQ int4 g128 vs FP8 W8A8-dynamic), so this compares engines as deployed,
  not kernels on equal bits. Axon has no FP8 path at all; the FP8 rows are their best on Hopper.
- **Cost: $3.09** for the pod (46 min at $3.99/h). The driver's own accounting: $2.96 paid, $1.46 useful
  (22.0 min of timed cells), $1.50 waste. Estimate was $4.36.

The gap is ESTIMATED to be two things (not profiled on the pod): Axon's batched-decode step at 64–128 rows on sm_90
(no decode-shaped wgmma / Marlin-class kernels; the step was tuned on sm_120 and sm_89), and admission / prefill
scheduling at high C (TTFT p99 and mix TPOT). See "What it means" below.

## Method

- **Client** (`sd_client.py`, stdlib): the same process and bodies for every engine, `/v1/chat/completions`
  streamed with `include_usage`. Closed loop: C threads, N = 2C requests (mix: N = max(16, 2C)). Every prompt starts
  with a unique 16-token salt, so no request hits another's prefix cache.
- **Workloads.**
  - *classic*: the [4090 cell](2026-10-18-c-curve.md)'s workload: a 519-token prompt, 512 tokens out.
  - *mix*: `prompts-mix-v2.jsonl` (128 entries, sha256 `c3ff5fb8…`): 104 short chat questions (max_tokens 256 or 512)
    and 24 long-context prompts of 1,998–7,665 tokens (max_tokens 256). Every prompt is counted with the served
    tokenizer so that prompt + salt + max_tokens + margin ≤ 8192. Which entries a cell gets rotates with (round, C),
    so mix cells at small C differ round to round by construction (the ±14–23 % spread at C = 8, for every engine).
- **Order.** Phase A (int4: Axon, vLLM-AWQ, SGLang-AWQ), then phase B (FP8: Axon again, vLLM-FP8, SGLang-FP8). Per
  phase: 2 rounds × 5 C, engines interleaved per C with the order rotated by round and C index; per visit: wake,
  8 untimed short requests, both workloads (order alternating), park. Axon is restarted per visit (no parking API).
  Axon runs in both phases, so **its row is the median of 4 cells, the others' of 2**. Its phase A and phase B cells
  agree within 2 % in every cell but mix C = 8 (the rotation above).
- **Metrics** per cell: aggregate tok/s (completion tokens / wall), TTFT p50/p99, ITL p50/p99 (inter-chunk gap),
  TPOT p50 (per-request decode time / tokens), goodput (tokens of the requests inside the SLO, / wall), the SLO
  fraction. Table cells are medians over rounds; the spread is max / min − 1.
- **Scale of the run:** 120 main cells + 4 control cells, 11,992 requests, **0 errors, 0 engine drops**, no engine in
  block mode (every park/wake self-test passed).

## What it means (ESTIMATED; nothing was profiled on the pod)

1. **Batched-decode GEMMs at 64–128 rows on sm_90.** Classic TPOT p50 grows 3.2 → 12.6 → 26.3 ms from C = 1 to 32
   to 128 (vLLM-AWQ 4.1 → 5.0 → 8.8). Axon's pool step was tuned on sm_120 and sm_89 (#81, #86): gemvm kernels at small
   row counts, then int8 `mma.sync` tiles (gemm2s; #100's 128 × 64 tile is routed only to passes of more than 64 tokens and
   the decode pool keeps gemm2s). On sm_90a, #33's wgmma + TMA kernel (gemmh2, 128 × 64 tiles, measured for prefill
   at 512–1050 tokens) also takes the fused Q4_K gate+up and the Q4_K products that fill a wave of its tiles; the
   3584-row q / o / down products at 128 rows, the Q6_K matrices of a Q4_K_M file and attention don't. Nobody has
   measured `pool_step_cost` on an H100. vLLM / SGLang run Marlin-class int4 and FP8 GEMMs built for Hopper. The
   work: a decode-shaped Hopper GEMM (wgmma, TMA, tiles for 64–256 rows, the Q6_K types too), measured by
   `pool_step_cost` on an H100 first.
2. **Admission and prefill scheduling at high C.** Mix TPOT (57.9 ms at C = 128) is 2.2× classic's (26.3 ms): the
   1,998–7,665-token prompts are chunked into the decode steps and every running stream pays for them. TTFT p99 at
   14.5 s (mix) / 6.6 s (classic) says the queue tail waits for whole waves. Serve's chunk budget and admission were
   tuned for ITL on a 12 GB laptop and a 4090 (#45, #55, #57), not for 128 streams.
3. **Not the KV capacity.** The paged pool had room for 128 full 8192-token sequences (1,048,576 tokens), so pages
   never ran short by construction, and the engine log has no preemption line.

A finer decomposition from the run's per-request data (prefill rate on a lone 7.6k prompt, the nb = 128 step against
its DRAM floor, CTA counts per product, the two-passes-per-step scheduler term) is in the outside review that
followed: [reviews/2026-10-19-outside-review-next-steps.md](../reviews/2026-10-19-outside-review-next-steps.md) §2.

What Axon can claim from this run: the fastest C = 1 stream on an H100 of the five (narrowly over SGLang-AWQ), a
1-second cold start against 42–71 s, and nothing else. It cannot claim datacenter throughput.

previous binary. Before spending on the pod, an exclusive A/B ran on avante: **job 1019-203211-9269** (`--timing
avante`, foreign GPU load 0 %), `ab-node.sh`: Qwen2.5-0.5B Q4_K_M, `serve --parallel 4 --ctx 8192`, C = 1, 2, 4,
classic + mix, 3 rounds, the two binaries interleaved per C.

| binary | classic C=1 / 2 / 4 | mix C=1 / 2 / 4 |
|---|---|---|

## What went wrong

- **The kit's hold-loop ssh hung for ~3.5 paid minutes.** `sd-pod.sh kit` started the pod's hold loop with
  `cd && setsid nohup sh -c '…' … & echo $!`, which kept the ssh session open, so the kit never returned. It was
  stopped and the rest run by hand: `pod_setup` started at 20:57:13 instead of ~20:53:30, which shows up as
  wait-setup. Fixed in axon-devstack `b5d0719`: kit and go start pod daemons in a `( … & )` subshell.
- **The watcher couldn't take the pod down.** `sd-pod.sh watch` ran as a systemd unit whose PATH lacked
  `~/.local/bin`, so its `axon-pods down` and `axon-run unhold` failed. Nothing was lost: the pod ended itself through
  the second path (driver DONE → watcher writes PULLED → `watchdog.sh now`), and the hold was released by hand. Fixed
  in the same commit (`sd-pod.sh` appends `~/.local/bin` to PATH).
- **No `meta/` snapshot was pulled** (pip freezes, `hw.txt`): engine versions above come from the engine logs and the
  pinned installs, and the driver version isn't recorded for this run.
- One pod, 2 rounds. Every margin under ~5 % in the tables (C = 1 vs SGLang-AWQ, the FP8 engines against each other)
  is not settled.

## Honest limits (runbook §10, updated)

- Different weights per row (Q4_K_M vs AWQ g128 vs FP8): engines as deployed, not kernels on equal bits. Quality
  wasn't measured; `requests.jsonl` keeps lengths and text hashes.
- Closed loop, N = 2C: the last wave runs below C (the same for every engine; the 4090 cell's method).
- No shared-prefix / agent workload: prefix caching is on for vLLM / SGLang and defeated by the salts; Axon's prefix
  reuse is defeated the same way.
- Axon at `--parallel 128` reserves nothing per slot any more (#71's pages); the runbook's "fixed slots" limit is out
  of date for c15c90e.
- Axon at `--numerics fast` doesn't exist ([ADR](../design/determinism-modes.md), proposed): every Axon number here
  is the bit-exact path.
