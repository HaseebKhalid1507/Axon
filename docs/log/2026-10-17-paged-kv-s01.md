# paged KV, stages 0 and 1: every cache kernel through a page table  

- Date: 2026-10-17. Branch: feat/paged-kv. Base: main cf68e9d. Status: open, not merged.
- Design: specs/r11-paged-kv.md (§1.2, §2.1–2.2, §3, §4 stages 0 and 1); forum "r11: paged KV design".
- **Must be rebased onto PR #60** (feat/serve-one-cache) before merge: #60 makes `CudaCache::kv` an
  `Rc<DevBuf>` with a `row0` view and edits `kv_args_at`; this branch's host diff is the few lines below.

## What changed
Stage 0 (commit e679e1e, kernel files + test):
- decode.cu `pg_row(tab, pos)` = `tab[pos / 64] * 64 + pos % 64` (null tab: `pos`); `PG_ROWS 64 == ATT_BLK`.
- `att_load` / `att_load_q8` take the tile's first cache row `rb` apart from its position `t0` (which stays the
  validity limit); `att_rb(tab, t0)` gives it. `attn_blk_t`, `attn_fa_bt`, `attn_fa_kt` take `tab` (default
  null) and load tile b from `tab[b] * 64`; `attn_blk_t`'s own one-row stores at np − 1 (q8 `kv_q8_store`,
  qwen3 `kc_out`) and the L2 re-read of that row's scales use `pg_row(tab, np − 1)`.
- Test-only wrappers `NAME_pg` (the attn_blk / attn_fa entry points with the table last) for the bit test;
  removed in stage 1.

Stage 1 (commit e7b8e0c):
- Kernels: the table is the last argument of every kernel that touches KV rows: `qkv_rope` (and
  `qkv_rope_f32`, which writes no row: unused), `attn_split_{64,128}`, `attn_split_q8*`, `attn_blk_*`,
  `attn_split_w_256`; batched `rope_kv_b`, `rope_kv_norm_b`, `kv_q8_b*`, `attn_split_b*`, `attn_blk_b*`,
  `attn_fa_b/bs/k*`, `rope_kv_norm_b_256`, `attn_split_bw_256`. `attn_split_t` reads row `pg_row(tab, lo + t)`:
  gemma3's window is now an integer `lo` added before translation (was a pointer offset), the split schedule
  still of `np − lo`. prefill.cu `rp_tab` / `rp_row` / `rp_base`: with `rp` and a table, `rp[2z + 1]` is the
  token's sequence's first entry in the pool's table.
- Host (qwen2.rs, batch.rs; one line each in slots.rs, stream.rs): `CudaCache::tab: Option<DevBuf>` (None on
  every production path; `set_tab` is `#[cfg(test)]` until stage 2's pool), `tab_at(e)`. `enqueue` passes
  `c.tab_at(0)`; `pass_at` uses `kv_args_at(c, l, 0)` plus the sequence's table (`Place::Seq` base = its first
  entry) when paged, else exactly as before; `layer()` takes `tab`; `upload_rows(rows, paged)` writes the table
  offset instead of `base + pos` for a paged cache. `stream_feed` asserts a plain cache (its host copies are of
  plain rows).
- Plain caches pass null everywhere, so every old path is the same code on the same addresses.

(The 30k prefix is 30000 random digits, one token each in Qwen's tokenizer: `gen` has no prompt file.)

## Not done / notes
- Stages 2+ (allocator, pool, serve policy): out of scope. Nothing in production can make a paged cache yet.
- No model-level `Place::Rows` test with a table (the pool owns the rows layout until stage 2); Rows-with-table
  is covered at kernel level (every batched kernel, rp offsets into a pool table).
- kvio / kvsave / `adopt_cache` / `layer_kv` copy plain rows; they go through the table in stage 2.
- The split kernel translates per row (no shared-memory cache of the tile's table entries, spec §2.2's optional
  optimisation); its null-table path is a uniform branch.
- kernel bit test: 3 random tables at np 32768 (20 below), each layout re-uploads the cache.
