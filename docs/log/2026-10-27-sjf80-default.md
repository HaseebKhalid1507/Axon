# `serve` defaults: shortest-first admission and an 80 ms step (PR #167)

- Date: 2026-10-27. Branch: feat/sjf80-default. Base: main 6f06544. Status: open (draft; gates in, the small-GPU cell ran on a 4090: the lead decides).
- Pick / design: issue #165 (H100 session r11), rule S, pre-registered verbatim from the Fable pick
  `specs/pick-r11-prefill.md` before any data; #139 had made `--step-ms 80` report-only.

## What changed
- `src/serve/engine.rs`:
  - `Sched::from_env`: shortest-first (`AdmitOrder::Sjf`) unless `AXON_ADMIT=fifo`.
  - `STEP_MS` 60 → 80.
  - The defaults are now the measured `sjf80` arm: shortest-first with lanes slots/16 in 2..8, `--admit-age-ms`
    3000, an 80 ms step at the measured cost.
- The scheduling of before is `--admit-order fifo --step-ms 60` (`AXON_ADMIT=fifo`). Adding `AXON_STEP_COST=legacy`
  gives the scheduling before #131, decision for decision.
- `AXON_ADMIT=sjf` from older configs still means sjf.
- Tests:
  - `legacy_alone_is_main_admission` and `serve_rollback_flags_reach_the_engine` assert the new defaults, whole,
    against `arm_sched("sjf80")`;
  - `serve_sd_ab` passes a fixed salt per (round, C) to the client and prints a BITS line across arms.
- `src/cli.rs` help, README (serve flags, environment table), docs/roadmap.md, START-HERE, results.md,
  benchmarks-gpu.md: the new defaults.

## Small GPUs: no-regression cell (pre-registered here, before it runs)
The flip was decided on an H100 at C = 64/128. On a 12 GB laptop GPU at low concurrency, the 80 ms step and sjf must
not regress:
- **Cell:** `serve_sd_ab`, 7B Q4_K_M, `--parallel 16 --ctx 8192` (bella's default pool), C = 1 and C = 4, arms fifo60
  vs sjf80, 3 rounds, fixed salt; `--timing bella --timing-fallback 4090`.
- **No regression iff**, at both C, as medians over rounds, sjf80 against fifo60:
  - aggregate ≥ −3 %;
  - short TTFT p50 ≤ +10 %;
  - ITL p50 ≤ +10 %;
  - ITL p99 ≤ 1.35× (the 80 / 60 step-budget ratio: the trade the rule accepted);
  - BITS identical.
- At C = 1 a lone request runs the solo path, so the arms should match to noise.
- If the cell fails, the PR does not land as is: the lead decides (for example, the old defaults below some
  `--parallel`).

## Results
- **Gates:**
  - md5 0 of 20 pairs differ (bella 1027-090607-ca07);
  - serve digests 1 per model over 10 runs (bella 1027-090608-2def);
  - `serve::` with `AXON_ADMIT=fifo` 138 passed, 0 failed (avante 1027-090607-bbfe);
  - the fast tier (1027-090606-5804) and the debug serve+slots run (1027-090606-b980) each failed one test, main's
    `pool_wide_long_steps_match_solo` (5.07 GiB pool on a 6 GB card). Main 6f06544 fails it the same way
    (1027-095951-0faf); fix #168.
- **No-regression cell: ran on an RTX 4090 pod, not on bella** (job 1027-090608-b6c6). It was registered
  `--timing bella --timing-fallback 4090`, and bella's desktop load blocked it for 20 min.
  - BITS 96/96 identical.
  - sjf80 against fifo60, medians of 3 rounds, 4090 numbers (MEASURED):
    - C=1: aggregate 175.6 vs 175.2 tok/s (+0.2 %), short TTFT p50 14.7 vs 14.7 ms, ITL p50 5.40 vs 5.41, ITL p99 6.12
      vs 6.08 (1.01×);
    - C=4: aggregate 473.6 vs 471.2 (+0.5 %), short TTFT p50 22.0 vs 21.0 (+4.8 %), ITL p50 6.52 vs 6.53, ITL p99 21.77
      vs 57.99 (0.38×).
  - Every threshold passes.
  - By the letter of the registered cell (the fallback was part of it), this run stands. By its stated purpose ("a
    12 GB laptop GPU at low concurrency"), it doesn't: on the 4090 the 80 ms step budget rarely binds at C = 4.
  - Settling the small-GPU claim needs the same cell on bella alone (`--timing bella`, no fallback, `--max-min 50`).
    The lead decides.
